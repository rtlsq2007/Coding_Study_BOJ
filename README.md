## ✅ 15552 - 빠른 A+B  
**문제 유형:** 반복문, 빠른 입출력  

### 📌 문제 설명  
테스트 케이스 T가 매우 크게 주어질 때, 각 줄마다 두 정수를 입력받아 합을 출력하는 문제이다.  
일반적인 입력 방식으로는 시간 초과가 발생할 수 있다.

### 🧠 배운 점  
- C++에서 입출력 속도 최적화 방법  
- sync 해제와 tie 해제의 역할  
- 시간 초과는 로직 문제가 아니라 입출력 문제일 수도 있다는 점  

### ✍ 느낀 점  
단순한 문제처럼 보였지만, 입출력 최적화의 중요성을 배울 수 있었다.

## ✅ 2439 - 별 찍기 - 2  
**문제 유형:** 반복문, 이중 반복문, 출력 패턴

### 📌 문제 설명
정수 N이 주어졌을 때 별(*)을 이용하여 오른쪽 정렬된 삼각형을 출력하는 문제이다.

### 💡 풀이 설명
각 줄마다 출력해야 하는 **공백과 별의 개수 규칙**을 찾아 구현하였다.

- i번째 줄의 공백 개수 → `N - i`
- i번째 줄의 별 개수 → `i`

따라서 한 줄을 출력할 때  
1. 공백을 먼저 출력하고  
2. 별을 출력하도록 구현하여 오른쪽 정렬을 만들었다.

### 🧠 배운 점
- 이중 반복문을 활용한 출력 패턴 구현  
- 공백과 별의 개수를 계산하여 정렬을 만드는 방법  
- 규칙을 찾으면 별 찍기 문제는 구조가 비슷하다는 점

### ✍ 느낀 점
처음에는 공백의 개수를 계산하는 부분이 헷갈렸지만 규칙을 이해하고 나니 별 찍기 문제는 반복문 패턴 문제라는 것을 알게 되었다.

## ✅ 10951 - A+B - 4  
**문제 유형:** 반복문, EOF 입력 처리

### 📌 문제 설명
두 정수 A와 B를 입력받아 합을 출력하는 문제이다.  
입력의 개수는 정해져 있지 않으며 **입력이 끝날 때까지 계속 처리해야 한다.**

### 💡 풀이 설명
입력 개수가 주어지지 않기 때문에  
입력이 정상적으로 들어오는 동안 반복문을 실행하도록 구현하였다.

C++에서는 `cin >> a >> b` 가 성공하는 동안 반복하도록 작성하면  
입력이 끝나는 순간 반복문이 종료된다.

### 🧠 배운 점
- 입력의 개수가 정해지지 않은 경우 처리 방법  
- EOF(End Of File) 기반 반복문 사용  
- 문제마다 입력 종료 방식이 다르다는 점

### ✍ 느낀 점
비슷한 A+B 문제라도 입력 종료 방식이 서로 다르다는 것을 알게 되었고, 문제의 입력 조건을 정확히 읽는 것이 중요하다는 것을 느꼈다.

## ✅ 10818 - 최솟값과 최댓값

**문제 유형:** 배열, 반복문, 최솟값/최댓값 탐색

### 📌 문제 설명

N개의 정수가 주어질 때, 최솟값과 최댓값을 출력하는 문제이다.

### 💡 풀이 설명

배열의 첫 번째 원소로 min과 max를 초기화한 뒤,  
반복문을 순회하며 현재 값이 max보다 크면 max를 갱신하고,  
min보다 작으면 min을 갱신하는 방식으로 해결하였다.  
처음에는 min과 max를 0으로 초기화하거나 하나의 if/else로 처리하려 했지만,  
두 조건이 완전히 독립적으로 비교되어야 한다는 것을 깨달았다.

### 🧠 배운 점

* min과 max는 서로 독립적으로 비교되어야 한다는 점
* 초기값 설정의 중요성 (0이 아닌 arr[0]으로 초기화)
* 불필요한 루프를 줄여 하나의 반복문에서 처리하는 최적화

### ✍ 느낀 점

로직이 단순해 보여도 초기값과 비교 조건 하나하나가 결과에 큰 영향을 미친다는 것을 느꼈다.

## ✅ 10810 - 공 넣기

**문제 유형:** 배열, 반복문, 구간 덮어쓰기

### 📌 문제 설명

N개의 바구니와 M번의 명령이 주어진다.  
각 명령 `i j k`마다 i번부터 j번 바구니까지 k번 공으로 덮어쓰는 문제이다.

### 💡 풀이 설명

M번의 명령을 반복문으로 처리하며,  
각 명령의 범위(from~to)에 해당하는 배열 인덱스를 k로 덮어쓰는 방식으로 해결하였다.  
배열이 1-based 인덱스라는 점을 고려하여 크기를 101로 선언하였다.

### 🧠 배운 점

* 구간 단위로 배열을 업데이트하는 방법
* 1-based 인덱스 처리 방식

### 🧠 배운 점

* switch문 대신 배열로 매핑을 처리하는 방식

### ✍ 느낀 점

## ✅ 10988 - 팰린드롬인지 확인하기

**문제 유형:** 문자열, 팰린드롬

### 📌 문제 설명

알파벳 소문자로 이루어진 단어가 주어질 때,  
해당 단어가 팰린드롬인지 확인하여 1 또는 0을 출력하는 문제이다.

### 💡 풀이 설명

`s[i]` 와 `s[s.length()-(i+1)]` 을 비교하며 양 끝에서 가운데 방향으로 순회하였다.  
문자열 길이의 절반만 비교하면 되므로 `s.length() / 2` 를 루프 조건으로 사용하였다.  
처음에는 홀수/짝수 길이를 별도로 처리했으나, 절반만 비교하면 두 경우 모두 동일하게 처리된다는 것을 깨달았다.  
단, 길이가 1인 경우 루프가 돌지 않아 별도 예외 처리가 필요하였다.

### 🧠 배운 점

* 팰린드롬 검사는 양 끝에서 가운데로 비교하는 패턴
* 홀수/짝수 길이 모두 `s.length() / 2` 로 동일하게 처리 가능하다는 점
* 길이가 1인 엣지 케이스를 항상 고려해야 한다는 점

### ✍ 느낀 점

처음에 홀수와 짝수를 따로 처리하려다 코드가 중복됐는데,  
결국 같은 로직이라는 것을 깨달으면서 코드를 단순화하는 사고방식을 배웠다.

런타임 에러, 배열 크기, 대소문자 처리, 중복 카운트 등 여러 문제를 하나씩 해결하면서

## ✅ 2941 - 크로아티아 알파벳

**문제 유형:** 문자열, 파싱

### 📌 문제 설명

크로아티아어에는 두 글자 또는 세 글자가 합쳐져 한 글자로 취급되는 알파벳이 있다.  
(`c=`, `c-`, `dz=`, `d-`, `lj`, `nj`, `s=`, `z=`)  
입력된 문자열이 실제로 몇 글자인지 출력하는 문제이다.

### 💡 풀이 설명

문자열을 앞에서부터 순회하며, 현재 문자가 크로아티아 알파벳의 시작 문자인지 확인하였다.  
크로아티아 알파벳에 해당하면 count를 1 증가시키고 i를 해당 글자 수만큼 이동,  
아니면 일반 알파벳으로 count를 1 증가시키는 방식으로 해결하였다.  
`dz=`는 세 글자가 한 글자이므로 `dz` 확인 후 `=` 를 추가로 확인하는 방식으로 처리하였다.  
또한 마지막 문자에서 `s[i+1]` 접근 시 범위를 초과할 수 있으므로  
`i+1 < s.length()` 조건을 모든 접근 전에 추가하여 안전하게 처리하였다.

### 🧠 배운 점

* 문자열을 앞에서부터 파싱하며 조건에 따라 인덱스를 다르게 이동하는 방법
* `i+1` 접근 시 항상 범위 체크를 해야 한다는 점
* 백준에서 맞아도 undefined behavior가 존재할 수 있다는 점
* 세 글자 조합(`dz=`)은 두 단계로 나눠 확인해야 한다는 점

### ✍ 느낀 점

테스트케이스를 통과했다고 해서 완벽한 코드가 아닐 수 있다는 것을 느꼈다.  
배열이나 문자열 접근 시 항상 범위를 먼저 확인하는 습관이  
게임 개발에서 예측하기 어려운 크래시를 막는 중요한 방어 코드라는 것을 배웠다.
